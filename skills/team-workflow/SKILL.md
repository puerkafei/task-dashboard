# 团队工作流

## 角色

| 角色 | agentId | 职责 |
|------|---------|------|
| 甄宓 | main | 总指挥 — 规划、Skill选择、工作流设计、status.json唯一维护、监控、呈报 |
| 曹操 | caocao | 执行经理 — 接收甄宓指令、按指定工作流分派、协调交接、催办、汇总交付 |

## 关键规则（固化，不可变）

| 事项 | 谁做 | 说明 |
|------|------|------|
| status.json 维护 | **仅甄宓（main）** | 不经过任何人中转 |
| 上传 GitHub | **coordinator.sh upload**（优先） / **貂蝉（OpenCode）** | 默认 coordinator.sh upload 自动上传；新建仓库/自定义 Release body 等需编码场景 → 貂蝉（OpenCode） |
| 下令上传 | **曹操（caocao）** | 需上传时判断类型：纯文件上传→指令含「使用 coordinator.sh upload」；需貂蝉编写→指令含「由你执行上传」|
| 汇总交付 | **曹操（caocao）** | 收集交付物 + 通知甄宓 |
| 呈报主公 | **仅甄宓（main）** | 不做总结摘编，原文呈报 |
| 工作流设计 | **仅甄宓（main）** | 曹操不得自行设计或修改工作流 |

## 任务执行铁律（防跳步、防越界）

1. **收到任务 → 必须先加载对应 Skill**，不得凭记忆或经验执行
2. **严格按工作流路径执行**，不得跳过任何环节
3. **各司其职，不越界：**
   - 曹操不写代码（归貂蝉）
   - 曹操不做调研（归诸葛亮）
   - 诸葛亮不写代码（归貂蝉）
   - 司马懿只审不退不写不改
4. **主公有指令变更 → 甄宓必须立即更新 status.json**，不得仅通过口头传递

## 状态流转

```
待分配 → 执行中 → 审核中 → 退回修改 → completed
```

## 通知链路

每个 Agent 完成环节后：
- **通知甄宓（main）** → 甄宓更新 status.json（主链路）
- **抄送曹操（caocao）** → 曹操协调下游交接（副链路）

## 卡点上报链路

任何 Agent 卡点 → 甄宓 → 主公
曹操卡点 → 甄宓 → 主公
甄宓卡点 → 主公

## 超时规则

| 对象 | 超时 | 动作 |
|------|------|------|
| 貂蝉未报告 | 16 分钟 | 曹操催办 → 无响应 → 上报甄宓 |
| 其他成员未报告 | 6 分钟 | 曹操催办 → 无响应 → 上报甄宓 |
| 审核无结论 | 6 分钟 | 曹操催办 |
| 下游未确认接收 | 5 分钟 | 卡点上报甄宓 |
| 甄宓未决策卡点 | 2 分钟 | 上报主公 |
| 甄宓未呈报交付物 | 1 分钟 | 超时卡点 |
